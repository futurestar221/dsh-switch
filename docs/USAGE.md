# 使用指南

本文说明 dsh-switch 的适用场景、首次配置、日常操作和风险注意事项。dsh-switch 是
非官方社区工具，不包含 DeepSeek Harness（DSH）本体，也不代表 DSH 官方。

## 1. 适用场景

dsh-switch 适合以下情况：

- 需要把工作、个人、测试等 DSH 使用状态分开，避免聊天记录、登录信息和插件互相污染。
- 想测试一套新插件或配置，但不想影响日常使用的 DSH 环境。
- 聊天记录和登录状态不变，只在一套 HOME 内切换插件与启动项组合。
- 把占用空间较大的 DSH 环境从一个目录迁移到另一个本机磁盘。
- 快速查看每个环境安装了哪些插件和技能。

它不负责以下工作：

- 不安装、不升级、不修改 DSH 程序本身。
- 不提供云同步、账号共享或多用户服务。
- 不保证第三方 DSH 版本、修改版或插件的兼容性。
- 不会自动合并两个同时使用的 HOME。

## 2. 先理解四个概念

| 概念 | 含义 |
| --- | --- |
| 环境 / HOME | 一套独立的 DSH 数据目录，包含聊天记录、登录信息、插件和 `profiles`。切换环境就是切换到另一套 HOME。 |
| 技能目录 / agents | 可选的 DSH 技能目录。可以和应用环境一起迁移，也可以单独指定。 |
| 配置方案 / profile | 同一个 HOME 内的一套插件和启动项组合。切换 profile 不更换 HOME，也不会清空聊天记录。 |
| 管理器数据 | dsh-switch 自己的配置、实例表、日志、回收站和运行状态，存放在 `%APPDATA%\dsh-manager`。 |

`%APPDATA%\dsh-manager` 继续使用旧目录名，是为了兼容已有安装；程序名和界面品牌是
`dsh-switch`。

## 3. 首次使用前

1. 关闭正在运行的 DSH，并保存未提交的工作。
2. 备份重要 HOME 和技能目录。迁移、切换和删除操作虽然带有校验与回收站，但任何
   文件操作都不应替代你自己的备份。
3. 给环境选择本机 NTFS 磁盘上的可写目录。建议不要使用系统目录、磁盘根目录、
   `Program Files`、只读目录、网络盘或正在同步的 OneDrive 目录。
4. 桌面版需要 Microsoft Edge WebView2 Runtime。没有桌面版时，`Start.cmd` 会尝试
   使用 Edge 应用模式或默认浏览器打开界面。

## 4. 启动和配置 DSH 路径

### 发布包

1. 解压发布包到一个可写目录。
2. 双击 `Start.cmd`。
3. 首次启动时打开“设置”，确认 `DeepSeek Harness.exe` 的路径。
4. 管理器会尝试从注册表、常见安装位置和快捷方式自动探测；探测失败时手动选择。

如果需要观察启动日志，可以运行发布包内的 `Start-Visible.cmd`；它只是保留控制台窗口，不会改变环境数据。

如果 Windows SmartScreen 提示未签名程序，请先确认文件来源和校验值，再决定是否运行。

### 源码目录

如果 `app\dsh-switch.exe` 不存在，`Start.cmd` 会回退到浏览器界面。构建桌面版的命令见
项目根目录的 `README.md`。

## 5. 新建或添加环境

在左侧点击“新建环境”：

- **新建空白环境**：目录必须不存在或为空，管理器会创建一套新的 HOME。
- **添加已有环境**：选择一个已经存在的 HOME，只登记路径，不修改里面的内容。

环境名可以包含中文，但不能包含 `\ / : * ? " < > |`。如果迁移、删除或同步环境，
建议使用容易辨认的名字。

## 6. 切换环境

1. 在左侧选中目标环境。
2. 点击“启动”或“切换到此环境”。
3. 如果已有 DSH 在运行，管理器会先关闭旧进程，再用目标 HOME 启动新进程。

DSH 桌面端同一时间只允许一个窗口，所以切换一定会关闭当前 DSH。切换前请保存正在
编辑的内容。不要手动同时启动两个指向不同 HOME 的 DSH 实例。

## 7. 使用配置方案（profile）

配置方案用于在同一个 HOME 内切换插件和启动项组合：

1. 先选中一个环境。
2. 在“当前配置方案”区域新建方案。方案名只能使用英文、数字、点、下划线、横线。
3. 停止 DSH 后选择目标方案，点击“切换方案”。
4. 如果切换结果不符合预期，可以使用“撤销上次切换”恢复上一套入口。

切换 profile 不会替换 HOME，也不会清除聊天记录和登录状态。`desktop` 是当前入口的
保留名，不要手动删除或重命名 `profiles\desktop`。部分 DSH 版本会忽略
`DSH_PROFILE`，因此管理器可能使用 Windows junction 维护入口。

## 8. 迁移环境目录

迁移会实际复制目录，而不是只修改一条记录：

1. 停止 DSH。
2. 选中环境，点击“迁移…”。
3. 填写新的绝对路径。目标应为不存在或空目录，不能与当前目录或其他环境互相包含。
4. 如果技能目录独立存放，可以选择一起迁移，并指定新的技能目录。
5. 管理器先复制到临时目录、校验文件数量和大小，再移动到目标位置并更新实例表。
6. 默认保留原目录；确认新目录可以正常启动后，再决定是否把原目录移入回收站。

迁移期间不要移动、删除或同时打开源目录/目标目录。若迁移失败，管理器会尽量保留
原环境；仍建议提前做外部备份。

## 9. 移除记录、删除目录和回收站

- **从列表移除**：只移除管理器记录，不删除任何文件。
- **删除目录…**：需要输入环境名确认，目录会先移动到管理器回收站，而不是立即抹除。
- **回收站恢复**：把目录放回原位置，并重新登记环境。
- **清空回收站**：真正删除目录，不可恢复。

删除前请确认环境已经停止，并再次确认路径确实是你想删除的 HOME 或技能目录。

## 10. 插件、技能和桌面快捷方式

- “插件 / 技能”面板是只读盘点，不会替你安装或卸载插件。
- 快捷方式管理只处理识别为 DSH 相关的桌面快捷方式。
- “隐藏”会把快捷方式移动到管理器备份目录，可以再次显示；管理器入口本身受保护。

## 11. 备份、恢复和卸载

### 备份

关闭 DSH 后，至少备份：

- 每个环境的 HOME；
- 如果单独使用，备份 agents / 技能目录；
- `%APPDATA%\dsh-manager`，其中包含实例表、配置、回收站和日志。

### 恢复

把 HOME 放回目标位置后，用“添加已有环境”登记。不要把备份直接覆盖到正在运行的
HOME；先停止 DSH，再处理文件。

### 卸载

1. 关闭 dsh-switch 界面和 DSH。
2. 删除程序目录即可移除程序本体。
3. 如需彻底移除管理器数据，删除 `%APPDATA%\dsh-manager`。这一步会同时删除管理器
   回收站里的内容，请先确认。
4. 管理器不会自动删除你的 DSH HOME、agents 或 DSH 程序文件。

## 12. 常见问题

### 找不到 DSH 程序

打开“设置”，手动选择 `DeepSeek Harness.exe`。如果你使用的是修改版或非标准安装，
自动探测可能找不到。

### 页面空白或提示后台服务已断开

先关闭管理器窗口，再双击 `Start.cmd`。如果仍失败，检查：

- `%APPDATA%\dsh-manager\dsh-manager.log`
- `%TEMP%\dsh-manager\native.log`
- WebView2 Runtime 是否安装
- 安全软件是否拦截了本地 `127.0.0.1` 服务

日志可能包含目录路径。发给别人前请先删除个人信息、用户名和完整路径。

### 无法切换 profile

确认 DSH 已停止。部分操作会锁定 `profiles\desktop`，运行中强行切换会造成配置损坏。

### 迁移提示目录非空或路径重叠

换一个不存在或空的目标目录，并确保新目录不在旧 HOME 里面，也不包含旧 HOME。

### 项目放在带空格的目录可以吗

可以。启动脚本和服务调用已经按带空格路径处理；如果遇到旧版本问题，请使用当前版本
重新启动。

## 13. 安全操作清单

- 操作前关闭 DSH，保存工作。
- 迁移和删除前先备份。
- 不要在 DSH 运行时手动改 `profiles`、HOME 或 agents。
- 不要把正在使用的 HOME 放在同步盘或网络盘。
- 不要随意创建 `disable-auth.txt`；它会关闭本地接口来源检查。
- 不要把包含完整路径和用户名日志直接发到公开 Issue。
- 只从可信来源下载发布包，并核对发布页给出的 SHA256。
